# Phase plan & record

Each phase ends with: working code + tests, PHASES record entry (below), DECISIONS updated. Keep record entries ≤5 lines.

## Plan

- **P0 — Research & scaffolding.** Survey references, audit draego FTS, settle architecture, write CLAUDE.md/SPEC/FORMATS/DECISIONS/PHASES. Gate: D1–D2 taken; D3–D7, D9 answered.
- **P1 — Core + MDX direct backend.** New Go module; `Dictionary`/`Lookuper`/`Reader` interfaces + capability tiers; inline `gomdict`; MDX/MDD direct lookup + resource serving; CLI `lookup`; golden tests on a small sample dict.
- **P2 — Ingest tier + query engine.** Canonical text.db schema; MDX ingester; ported draego query modes with all SPEC §FTS-audit fixes; concurrent all-dicts fan-out across mixed backends; driver benchmark settles D4; hostile-input FTS tests (`-`, `*`, `"`, `NEAR`, emoji).
- **P3 — StarDict + Slob.** Each: direct `Lookuper` (idx binary search / in-memory refs) + `Reader` for ingest + resource resolver (res dir/zip, slob bins). Sample-file tests.
- **P4 — DSL.** Lexer + →HTML transform (port rules from pyglossary dsl plugin), encodings (UTF-8/16/32+BOM), `.dsl.dz`, `.files.zip` resolver; transparent auto-ingest on first open. Heaviest parsing work — isolated phase.
- **P5 — HTTP server & API + full ingest.** Config layering from mdict-go-web; endpoints per SPEC §6; per-dict "Enable fuzzy & full-text search" flow with SSE progress; `ingest=full` media.db packing + uuid pairing + resolution order.
- **P6 — UI.** draego chrome (sticky bar, accordion, vendored mark.js) + Shadow-DOM article sandboxing; per-dict CSS into shadow roots; φ-scale spacing; mobile; dark mode (mdict-go-web/notes/dark-mode.md).
- **P7 — Polish & release.** Cross-platform builds, Makefile, README.md, stale-source handling UX, perf pass, error-path hardening.
- **P8+ — user-directed batches** (no pre-written plan; each lands as a record entry below): P8/P8.1 performance & progressive UX, P9 audit fixes & URL/MIME correctness, P10 native-ingested overhaul (+BGL), P11 preview-cost & in-process Speex. Standing backlog: `code-review.md`, prioritized by D15.

### P12 — The library: private, consented, one folder per dictionary — 2026-07-27 — COMPLETE (uncommitted)
Investigation of three reported symptoms (a phantom `wudict:slob` row, the setup page never appearing, `--dict-dir <db dir>` triple-listing AHD5) traced them all to one design leak: D17 made the app's private cache a dictionary discovery root. Fixed as **D19** (phase 1) + **D20** (phase 2), user-directed. **D19**: `store` registers `text.db` (exact name) + `.text.db` instead of bare `.db` — a `media.db` sidecar can no longer open as a dictionary anywhere; `DICT_DIR == DB_DIR` is a hard startup error (canonical paths) and `dict.ExcludeDir` skips the library subtree wherever it sits; the library is listed only under `USE_CACHED` (default off), which restores `reg.Count()==0` as a correct first-run signal with no special-casing; the setup page gained a "Previously imported dictionaries" section (`GET /api/library`, badges, **Use these dictionaries**) plus an "also keep my N…" checkbox — three outcomes (folder / library / both), the click *is* the consent and persists `USE_CACHED=1`. **D20**: flat `<slug>-<hash8>.text.db` → `<db dir>/<source name>/{text.db, media.db, info.txt}`; naming mirrors the source file with a format tag on collision (`AHD5-2017 (mdx)`, never a hash); allocation is an atomic `os.Mkdir` **claim** so concurrent first ingests can't collide, while read paths use a non-creating `LookupDir` (browsing never litters the library); `info.txt` is a regenerated receipt whose `source` line is the **ownership record** — deliberately outranking meta's `source_path`, which a reader may report relative or empty (caught by a real failure: the fake-format fixture reported `x.fake` and orphaned its own folder); staleness moved from the file name into the meta (`SourceChanged`: size+mtime, hash only on mismatch → re-index in place, no `-oldhash` pile-up, "superseded" gone as an orphan class); `clean` is folder-aware; pre-D20 flat databases are **adopted** (renamed into folders at startup by `store.AdoptLoose`, never re-indexed or deleted) after the first cut wrongly made them `clean` fodder — which left a real library listing nothing and would have forced re-preparing data the app already had. Also: `--use-cached` flag, help/README/config template, panel shows the transferable **folder**, and a `TestMain` now pins `WUDICT_DB_DIR` for the server package after background auto-ingests were caught writing into the real `~/.wudict/db`. New tests: folder naming/collision/ownership/staleness/library listing, media.db-is-never-a-dictionary end-to-end, setup consent flow, bundle discovery + exclusion. Live-verified: guard, setup→consent→search, dedup with sources present, a handed-over folder used from a dictionary folder, `clean` dry run.
