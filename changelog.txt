v3.7.11

🚀 Features
(config) COMPRESSION = "zstd" | "deflate" | "none", optionally with a level ("zstd-3", "deflate-6"); --compression on serve. NO_COMPRESS and "fast"/"small" are still read and reported with the new spelling
(android) Settings → Advanced: Article compression (zstd, DEFLATE or none) replaces the "uncompressed" switch; a ticked switch becomes "none"

⚡ Performance
(index) Article text is stored with zstd with custom trained dict build from articles: indexed dictionaries are about 28% smaller than with DEFLATE, articles decompress about 4 times faster, and compressing uses less CPU. Earlier dictionaries keep working and are shown as outdated: Rebuild (or wudict reindex) converts them. A dictionary indexed this way does not open in earlier wudict versions: COMPRESSION = "deflate" keeps the old form

v3.7.9

🚀 Features
(panel) Set custom dictionary name via panel > About this dictionary > Rename
(stardict) Show the images, sound, video and attachments listed in StarDict resource ('r') entries; prepared StarDict dictionaries are marked outdated, and refreshing one picks it up
(intake) Install dictionaries up to 256 GB (full Wikipedia ZIMs); a download or install that would not fit is refused up front, saying how much space it needs
(history) Favourites and history: star words with ☆ next to the search box; your history and favourites show under the empty search box
(search) Case and accents rank results instead of excluding them: corazon finds corazón, March finds march and March, in exact, prefix and wildcard search; results in dictionary order
(desktop) The tray icon opens wudict; a server bound to every address shows its LAN addresses
(browse) Indexing progress shown while a new dictionary is prepared for browsing
(config) COMPRESSION = "small" in wudict.toml: a library 1-2% smaller, indexing up to 1.5× as long; "fast" stays the default

⚡ Performance
(zim) Wikipedia-scale ZIM files open without loading their index into memory; images and video are served straight from the file
(slob) Large .slob files open instantly and use about half the memory (6.2 GB OED: 530 → 279 MB)
(prepare) Dictionaries made mostly of redirects (@@@LINK) prepare up to 2× faster
(wildcard) Patterns that start with a non-Latin letter (Cyrillic, Hebrew, CJK…) run up to 80× faster on large dictionaries
(slob) The first search in a large .slob that is not prepared yet is about 1.5× faster
(prepare) Large dictionaries index 6-9× faster while you wait on them, 2× faster in the background (17 GB wudict markdown OED: 4:44 → 35 s; 1.1 GB Spanish Wiktionary: 2:03 → 19 s), with the same content
(prepare) Article text is compressed in parallel with a faster compressor; rows are written 256 at a time
(wudict markdown) Two parses instead of three, in parallel; a reference-style file with many link definitions no longer slows down quadratically
(memory) Indexing uses free RAM within a budget (half of what is free, at most 1/8 of the machine; on Android half of the app's memory limit) and falls back to one core when it runs out; background indexing stays on one core
(zim) ZIM optimizations

🐛 Bug Fixes
(media) Audio and video from MDict, slob, ZIM and Babylon dictionaries, and from prepared ones without a media pack, now support seeking (browsers such as Safari need it to play video); Speex audio converted to WAV too
(mdx) Chinese MDict dictionaries declaring GB18030 no longer show garbled text; prepared MDict dictionaries are marked outdated, and refreshing one picks it up
(stardict) Wikipedia-scale compressed indexes (.idx.gz over 256 MB) are no longer refused
(stardict) A quote in an XDXF cross-reference no longer breaks the link
(media) A media pack no longer fails as a whole because one file is over 1 GB
(ui) Theme, layout and dictionary choices apply even when the browser cannot store preferences
(build) Release workflows: blank-tag purego release, one version stamp for all assets, Actions on Node 24; make run/open/purge and apk-play-release fixes
(zim) Some ZIM files failed to open
(config) NO_COMPRESS and the Android memory limit now apply to the indexing that starts with the server
(browse) Clicking a headword in Browse selects its dictionary in the dictionary picker
(title) A custom dictionary title is used in the article sections too
(windows) Explorer no longer opens on launch
(ui) Typing / to focus the search box shows it if it is hidden
(ci) macOS builds on macos-15
